## 2. 버전번호 표시

### 2.1 표시 위치

**헤더 우측**에 배치했습니다.

```
┌────────────────────────────────┐
│      DayPick          v1.0.1   │  ← sticky 헤더
├────────────────────────────────┤
│ 표시 기간   [ 2주 (15일) ▼ ]   │  ← sticky 설정 바
├────────────────────────────────┤
│  2026-08-07(금)      [오늘] 📋 │
```

선정 근거:
- sticky 헤더 안에 있어 스크롤해도 항상 확인 가능 (12주=85개 목록에서도 유효)
- `position: absolute` 로 띄워 중앙 정렬된 "DayPick" 제목의 위치를 밀지 않음
- 반투명 흰색 0.72rem 이라 주 기능(날짜 목록)에서 시선을 뺏지 않음

### 2.2 마크업

```html
<div class="top-bar">
  <header>
    DayPick
    <span class="app-version" id="appVersion"></span>
  </header>
  ...
</div>
```

기존에는 `<header>` 자체가 `position: sticky` 였으나, 설정 바를 헤더와 함께 고정하기
위해 `.top-bar` 래퍼로 감싸고 sticky/box-shadow를 래퍼로 이관했습니다.

### 2.3 스타일

```css

}

  ...
}

```

### 2.4 버전 정의 위치 (3곳)

| 파일 | 코드 | 역할 | 필수 |
|------|------|------|------|
| `index.html` | `const APP_VERSION = '1.0.1';` | 헤더 표시 (권위) | O |
| `sw.js` | `const CACHE_NAME = 'daypick-v1.0.1';` | **PWA 캐시 무효화** | O |
| `manifest.json` | `"version": "1.0.1"` | 매니페스트 메타데이터 | - |

`sw.js` 의 `CACHE_NAME` 을 함께 올리는 것이 핵심입니다. Service Worker가 Cache-First
전략이므로 캐시명이 그대로면 기존 설치 사용자에게 새 버전 파일이 내려가지 않습니다.
캐시명이 바뀌면 `activate` 이벤트의 정리 로직이 이전 캐시를 삭제합니다.

```js
// sw.js
const CACHE_NAME = 'daypick-v1.0.1';

self.addEventListener('activate', (event) => {
  event.waitUntil(
    caches.keys().then((keyList) =>
      Promise.all(keyList.map((key) => {
        if (key !== CACHE_NAME) return caches.delete(key);   // 이전 버전 캐시 폐기
      }))
    )
  );
  self.clients.claim();
});
```

### 2.5 렌더링

```js
document.getElementById('appVersion').textContent = 'v' + APP_VERSION;
```

HTML에 `v1.0.1` 리터럴을 넣지 않고 JS 상수에서 주입합니다. 버전 정의 지점을
`APP_VERSION` 한 곳으로 모아 `09_ChangeVersionName.py` 의 치환 대상을 단순화했습니다.

## 3. 표시 기간 설정 (localStorage)

### 3.1 UI

헤더 바로 아래 sticky 설정 바에 `<select>` 드롭다운을 배치했습니다.

```html
<div class="settings-bar">
  <label for="weeksSelect">표시 기간</label>
  <select id="weeksSelect" aria-label="표시할 주간 수"></select>
</div>
```

네이티브 `<select>` 를 사용해 모바일에서 OS 기본 피커가 뜨도록 했습니다.
기본 화살표는 `appearance: none` 으로 제거하고 SVG data URI 로 교체해
플랫폼 간 외형을 통일했습니다.

```css
#weeksSelect {
  appearance: none;
  -webkit-appearance: none;
  background: #F5F5F5;
  background-image: url("data:image/svg+xml,%3Csvg ... polyline points='6 9 12 15 18 9' ...%3E");
  background-repeat: no-repeat;
  background-position: right 9px center;
  background-size: 14px 14px;
  padding: 6px 30px 6px 12px;
  min-height: 36px;                        /* 터치 타깃 확보 */
  border: 1px solid #BDBDBD;
  border-radius: 6px;
}

#weeksSelect:focus {
  outline: none;
  border-color: #1976D2;
  box-shadow: 0 0 0 2px rgba(25,118,210,0.2);
}
```

### 3.2 설정 상수

```js
const STORAGE_KEY = 'daypick.weeks';   // localStorage 키
const DEFAULT_WEEKS = 2;               // 기본값: 2주 (v1.0.0 과 동일)
const WEEK_OPTIONS = [1, 2, 3, 4, 6, 8, 12];
```

### 3.3 주간 수 → 날짜 개수

```js
function weeksToDayCount(weeks) {
  return weeks * 7 + 1;   // N주 전까지 + 오늘
}
```

| 선택 | 표시 개수 | 선택 | 표시 개수 |
|------|----------|------|----------|
| 1주 | 8일 | 6주 | 43일 |
| 2주 | 15일 | 8주 | 57일 |
| 3주 | 22일 | 12주 | 85일 |
| 4주 | 29일 | | |

### 3.4 localStorage 입출력

```js
function loadWeeks() {
  try {
    const saved = parseInt(localStorage.getItem(STORAGE_KEY), 10);
    if (WEEK_OPTIONS.indexOf(saved) !== -1) {
      return saved;
    }
  } catch (err) {
    // 시크릿 모드 등 localStorage 사용 불가 - 기본값 사용
    console.warn('설정 불러오기 실패:', err);
  }
  return DEFAULT_WEEKS;
}

function saveWeeks(weeks) {
  try {
    localStorage.setItem(STORAGE_KEY, String(weeks));
  } catch (err) {
    console.warn('설정 저장 실패:', err);
  }
}
```

방어 처리 2가지:
1. **예외 방어** — 시크릿 모드/저장소 차단 환경에서 `localStorage` 접근이 예외를
   던져도 앱이 멈추지 않고 기본값으로 동작
2. **값 검증** — 저장값이 `WEEK_OPTIONS` 화이트리스트에 없으면 기본값으로 폴백.
   `parseInt` 특성상 `"2.5"` → `2`, `"abc"` → `NaN` 이 되는데, `indexOf` 검사로
   허용 목록에 있는 정수만 통과시킵니다.

### 3.5 드롭다운 초기화 및 변경 처리

```js
function initSettings(weeks) {
  const select = document.getElementById('weeksSelect');

  WEEK_OPTIONS.forEach(function (w) {
    const opt = document.createElement('option');
    opt.value = String(w);
    opt.textContent = `${w}주 (${weeksToDayCount(w)}일)`;
    select.appendChild(opt);
  });

  select.value = String(weeks);

  select.addEventListener('change', function () {
    const w = parseInt(select.value, 10);
    saveWeeks(w);
    renderDates(w);
    showToast(`최근 ${w}주 (${weeksToDayCount(w)}일) 표시`);
  });
}
```

옵션 목록을 HTML에 하드코딩하지 않고 `WEEK_OPTIONS` 에서 생성하므로,
선택지를 늘리려면 배열 한 줄만 수정하면 됩니다.

CP949/UTF-8 인코딩 문제를 원천 회피합니다.

### 5.3 09_ChangeVersionName.py

원본(LinkTurnAd)의 4개 대상(package.json / AdDisplay.jsx / ControlPanel.jsx /
browserShim.js)을 DayPick의 3개 대상으로 교체했습니다.

```python
SCRIPT_DIR = Path(__file__).parent
APP_DIR = SCRIPT_DIR / "DayPick"

INDEX_HTML = APP_DIR / "index.html"
SW_JS = APP_DIR / "sw.js"
MANIFEST_JSON = APP_DIR / "manifest.json"

SEMVER = r'\d+\.\d+\.\d+(?:[-+][0-9A-Za-z.\-]+)?'
```

치환 패턴:

| 대상 | 패턴 | 필수 |
|------|------|------|
| index.html | `(APP_VERSION\s*=\s*')SEMVER(')` | O |
| sw.js | `(CACHE_NAME\s*=\s*'daypick-v)SEMVER(')` | O |
| manifest.json | `("version"\s*:\s*")SEMVER(")` | - |

원본의 핵심 특성은 그대로 유지했습니다.
- `newline=''` 로 원본 줄바꿈(CRLF) 보존
- `utf-8-sig` 로 BOM 안전 읽기
- 필수/선택 대상 구분 후 필수 실패 시 exit code 1
- 이미 해당 버전이면 `= ... 이미 X.X.X (변경 없음)` 출력 후 파일 미기록

다음 단계 안내는 `10_BuildAll.py` → `11_DeployToPages.py` 로 변경했습니다.
